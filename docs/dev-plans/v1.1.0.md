## 二、v1.1.0 版本目标

### 2.1 版本定位

**主题：生产可用基础 + 播放体验补全**

v1.1.0 当前保留这些交付目标：

1. 桌面小组件：提供基础播放控制和当前歌曲展示。
2. 播放队列拖拽排序：在现有播放队列中调整顺序。
3. 交叉淡入淡出 / 无缝播放：优化歌曲切换听感。
4. JaCoCo 排除范围缩小：补测试并减少覆盖率盲区。
5. 发布收口：版本号、备份规则、主链路回归和 release 构建。

## 四、详细任务

### 4.1 P1 桌面小组件

**目标：**实现 4x1 迷你控制器和 4x2 封面控制器。

| 子任务 | 内容 | 预计工时 |
|--------|------|---------:|
| 4.1.1 | 新建 `ui/widget` 包和 Widget 状态模型 | 1h |
| 4.1.2 | 新建 `music_widget_info.xml`，定义尺寸、预览和 resize 模式 | 1h |
| 4.1.3 | 实现 4x1 小组件布局：标题、歌手、播放/暂停、上下首 | 2h |
| 4.1.4 | 实现 4x2 小组件布局：封面、歌曲信息、播放控制 | 2h |
| 4.1.5 | 实现 Widget Receiver / Action 入口，连接 `PlayActionDispatcher` | 2h |
| 4.1.6 | 播放状态变化后触发 `GlanceAppWidget.updateAll()` | 1.5h |
| 4.1.7 | 点击小组件打开 `MainActivity`，兼容无播放状态 | 1h |
| 4.1.8 | Manifest 注册与桌面兼容性验证 | 1.5h |
| 合计 |  | 12h |

实现约束：

- Glance 依赖已经添加，不再新增依赖任务。
- 小组件第一版不做周期后台刷新，不引入 WorkManager。
- 状态来源优先复用 `PlayStateObserver`、`PlayStateDataStore`、`SongRepo`。
- 控制动作统一转成 `PlayAction.TogglePlay` / `Prev` / `Next`，避免小组件绕过播放核心。

### 4.2 P2 播放队列拖拽排序

**目标：**PlayQueue 支持拖拽重排，并保持播放核心行为正确。

| 子任务 | 内容 | 预计工时 |
|--------|------|---------:|
| 4.2.1 | 为 `PlayAction` 增加队列移动动作，或在 VM 暴露移动方法 | 1h |
| 4.2.2 | 复用 `PlayQueueRepo.swapItems()` 完成顺序交换 | 1h |
| 4.2.3 | `PlayerSession` 增加移动后刷新预加载逻辑 | 1h |
| 4.2.4 | `PlayQueue` 实现拖拽 UI 和拖拽 handle | 2h |
| 4.2.5 | 处理当前播放项、高亮、分页快照和拖拽边界 | 1h |
| 4.2.6 | 顺序播放 / 随机播放 / 删除队列后的回归验证 | 1h |
| 合计 |  | 7h |

重要修正：

- 不新增 `QueueEntity.sortOrder` 字段。
- 不对 `play_queue` 表新增 `sort_order`。
- 当前表已经是 `play_queue(sort_order TEXT NOT NULL, shuffle_order TEXT NOT NULL)`。
- 拖拽排序只调整现有 order 值，并刷新当前预加载队列。

### 4.3 P3 播放衔接增强

**目标：**补齐交叉淡入淡出和无缝播放，改善连续播放体验。

| 子任务 | 内容 | 预计工时 |
|--------|------|---------:|
| 4.3.1 | 梳理 `PlayerSession` / `MediaPlaybackController` 当前切歌链路 | 1h |
| 4.3.2 | 无缝播放：稳定 current + next 预加载和自动切歌衔接 | 2h |
| 4.3.3 | 交叉淡入淡出：实现音量渐变和下一首提前启动策略 | 3h |
| 4.3.4 | 增加设置项：关闭 / 3s / 5s 淡入淡出时长 | 1.5h |
| 4.3.5 | 处理边界：手动切歌、seek、暂停、Repeat One、队列删除 | 1.5h |
| 4.3.6 | 播放衔接回归与问题修复 | 1h |
| 合计 |  | 10h |

实现约束：

- 默认保持现有播放行为，交叉淡入淡出需可关闭。
- 无缝播放优先保证顺序播放和随机播放场景。
- `REPEAT_ONE` 不触发跨歌曲淡入淡出。
- 如果单播放器方案无法稳定实现交叉淡入淡出，应在控制器层评估双播放器过渡方案，并保留开关兜底。

### 4.4 P4 JaCoCo 排除范围缩小

**目标：**减少当前覆盖率盲区，优先把可单测的纯逻辑和轻 Android 依赖逻辑纳入覆盖。

| 子任务 | 内容 | 预计工时 |
|--------|------|---------:|
| 4.4.1 | 审核当前 `jacocoFileFilter`，标记可移除排除项 | 1h |
| 4.4.2 | 补充 `PlayerSession` 可测分支或提取纯逻辑测试 | 2h |
| 4.4.3 | 补充 DataStore / Settings 相关测试或保留必要排除说明 | 1.5h |
| 4.4.4 | 补充播放衔接、队列排序相关单测 | 1h |
| 4.4.5 | 更新 JaCoCo 排除规则，避免继续排除可测业务逻辑 | 1h |
| 4.4.6 | 执行覆盖率报告和验证任务，修复覆盖率失败 | 1.5h |
| 合计 |  | 8h |

收口原则：

- 不强行取消所有 Android framework 相关排除。
- 优先收窄 `PlayerSession`、DataStore、扩展函数等可通过抽象或 fake 测试的范围。
- 覆盖率门槛保持可执行，不能为了数字引入脆弱测试。

## 七、风险与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| Glance 状态刷新不稳定 | 小组件状态滞后 | 先做用户操作和播放状态变化触发刷新，周期刷新延期 |
| 队列拖拽影响预加载 | 下一首播放错误 | 拖拽后刷新当前歌曲的 next preload |
| 交叉淡入淡出实现复杂 | 播放器稳定性下降 | 保留开关，必要时先稳定无缝播放，再启用淡入淡出 |
| 无缝播放受音源编码影响 | 个别歌曲仍有空隙 | 优先保证播放器侧不主动制造空档，并记录音源限制 |
| JaCoCo 收窄导致覆盖率任务失败 | CI 阻塞 | 分批移除排除项，失败时补测试或保留必要排除说明 |
| 备份恢复路径失效 | 新设备恢复后播放失败 | 不备份播放进度和临时队列 |
| 范围再次扩大 | 排期失控 | 收藏和播放列表增强默认延期，重新加入时需要重新评估 |

## 八、延期到 v1.2.0

以下内容不纳入 v1.1.0：

- 收藏能力
- 播放列表重命名
- 播放列表封面
- 在线歌词源接入
- 歌曲标签查看与编辑
- 引导页 / 首次启动体验
- 音频可视化
- 播放列表导入导出 `.m3u`
- Android Auto
- Chromecast
- 手势切歌
- 主题或插件系统
- PlayerSession 深度可测性重构
- WorkManager 周期刷新小组件
